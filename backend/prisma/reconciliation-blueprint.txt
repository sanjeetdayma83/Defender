AUTHORITATIVE DATABASE
----------------------

Existing production tables and data must not be renamed, dropped,
or recreated merely to satisfy the current application schema.

MIGRATION SAFETY RULES
----------------------

DO NOT run:
  prisma migrate deploy
  prisma migrate resolve
  prisma db push
  prisma migrate reset

until the reconciled schema validates against production.

DO NOT rename production tables.

DO NOT drop production tables.

DO NOT recreate production tables.

DO NOT modify production data as part of schema reconciliation.

The failed migration:
  20260926021320_initial_loss_defender_schema

must be handled only after the Prisma schema has been reconciled.


TARGET
------

Create one canonical Prisma schema capable of:

1. Reading all existing production data.
2. Writing existing production entities safely.
3. Supporting current backend services.
4. Preserving existing billing/invoice data.
5. Preserving recording/evidence/claim workflows.
6. Supporting RBAC.
7. Supporting storage/evidence services.
8. Supporting future application-domain extensions without
   corrupting the existing production model.
